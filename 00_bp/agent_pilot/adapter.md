# Pilot Adapter Contract

> Status: draft · Version 0.1 · **Current tier: Prop**

An **adapter** is a standalone program that bridges a messaging service
to the Pilot REST API (`C6`). Adapters are **outside the agent core and
outside the build gate**: any messenger can be added without touching
Pilot, and a broken adapter can never fail the Pilot gate. The runtime
contract is frozen in [channel.schema.json](channel.schema.json) and
[http-api.schema.json](http-api.schema.json); this document is the
author-facing summary.

First-party reference adapters (Telegram, Signal) are specified by this
document and **generated by the builder** from the blueprint, like every
other Pilot component. They run as separate programs, outside the agent
binary and outside the gate.

## Configuration

An adapter is configured by environment variables, so it stays
language- and deployment-agnostic:

| Variable | Meaning |
| --- | --- |
| `PILOT_URL` | Base URL of the served agent (default `http://127.0.0.1:7363`). |
| `PILOT_TOKEN` | The bearer token (`C10`). Required. |
| `CHANNEL_ID` | The channel this adapter serves (default: the adapter name). Must match a channel registered in Pilot (`channels`, `C6`) or inbound POSTs get `404`. |
| `OUTBOUND_PORT` | Local port the adapter listens on for outbound pushes. Register it as the channel's `outbound_url` (`http://<host>:<port>/`). |
| service credentials | e.g. `TELEGRAM_BOT_TOKEN`, `SIGNAL_NUMBER` — the adapter's own; they are never sent to Pilot. |

## Inbound (messenger → Pilot)

For each message, `POST {PILOT_URL}/channels/{CHANNEL_ID}/messages`
with header `Authorization: Bearer {PILOT_TOKEN}` and body
`{from, text}` ([channel.schema.json](channel.schema.json)
`inboundMessage`).

| Status | Meaning | Adapter action |
| --- | --- | --- |
| `2xx` | accepted, runs as a goal | continue |
| `401` | bad/missing token | stop, report a config error |
| `403` | sender not permitted (`allow_from`) | drop, do not retry |
| `404` | unknown channel | stop, report a config error |
| `5xx`/transport | transient | retry with bounded backoff |

## Outbound (Pilot → messenger)

The adapter runs a small HTTP server. Pilot `POST`s `{to, text, at,
task?}` ([channel.schema.json](channel.schema.json) `outboundMessage`)
to the channel's `outbound_url`. When the channel has an
`outbound_secret`, Pilot sends `Authorization: Bearer <value>` (the
value resolved from the secrets store, `C10`) and the adapter must
require it. The adapter forwards the text to the messenger and returns
`2xx`; a non-`2xx` is retried by Pilot on its next tick (`C8`).

## Rules

- One adapter = one channel = one session (`C5`, channel-keyed).
- An adapter is a **dumb pipe**: no reasoning, no memory, no model; it
  maps messages both ways and nothing else.
- It never logs message bodies or the Pilot token, and never sends its
  service credentials to Pilot.
- Text only (`C7`); attachments are out of scope at Pilot.
